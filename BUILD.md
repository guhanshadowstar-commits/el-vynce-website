# EL VYNCE — build notes

The site is plain static HTML/CSS/JS and needs **no build step to run** — open the
pages or push to GitHub Pages and they work.

The one exception is the CSS. Tailwind used to run live in every visitor's
browser via `cdn.tailwindcss.com` (~400 KB downloaded and compiled on every
visit). It's now **compiled ahead of time** into `css/tailwind.css`, which every
page loads. This makes pages load much faster.

## When do I need to rebuild the CSS?

Only when you **add or change a Tailwind utility class** in an `.html` file or in
`js/*.js` (e.g. you add `class="mt-8 text-secondary"` somewhere new). Editing
text, images, links, or your own `css/style.css` does **not** need a rebuild.

If you add a class and it seems to do nothing, you probably just need to rebuild.

## How to rebuild (one time setup, then one command)

First time only — install the tools:

```
npm install
```

Then, any time you change classes, regenerate the stylesheet:

```
npm run build:css
```

That writes a fresh minified `css/tailwind.css`. Commit it and deploy.

Tip: while editing, you can run `npm run watch:css` and it rebuilds automatically
every time you save an HTML/JS file.

## Notes

- `tailwind.config.js` holds the brand theme (colors, spacing, fonts). It mirrors
  the old inline config exactly, so the look is unchanged.
- `node_modules/` is not committed (it's regenerated by `npm install`).
